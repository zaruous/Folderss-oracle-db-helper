## 1. 이력이 답해야 할 질문

DBA가 "이력"으로 알고 싶은 것은 네 가지다. 질문마다 필요한 데이터·기간이 달라서 하나의 저장 방식으로 다 풀리지 않는다.

| # | 질문 | 필요한 것 | 기간 |
|---|---|---|---|
| Q1 | 지난 5분 동안 무엇이 느렸나 | 누적 카운터(느린 SQL·대기 이벤트)의 **두 시점 차이** | 분 |
| Q2 | 세션·잠금·사용률이 지금 늘고 있나 | 숫자 지표의 짧은 추이(스파크라인) | 분~시간 |
| Q3 | 테이블스페이스가 며칠 뒤 가득 차나 | 사용량의 **일 단위** 추세 | 주~달 |
| Q4 | 아무도 안 볼 때 문제가 생겼나 | 상시 수집 + 알림 | 상시 |

## 2. 바꿀 수 없는 제약 (설계의 허점이 되기 쉬운 곳)

1. **플러그인은 Folderss가 켜져 있고 모니터 창이 열려 있을 때만 돈다.** 백그라운드 서비스가 없다. 그래서 플러그인 안에서 모은 이력은 언제나 **구멍이 있다**(밤·주말·PC 꺼짐). Q4는 플러그인만으로는 풀 수 없다.
2. **여러 사람·여러 PC가 같은 DB를 본다.** 로컬 파일 이력은 PC마다 따로이고 서로 다르다.
3. **운영 DB에 테이블·잡을 만드는 것은 보통 허용되지 않는다**(DBA 승인·변경 관리 대상).
4. **플러그인 계약에 알림 기능이 없다**(`IPluginManager`에는 설정·데이터 폴더·폴더 패널·설정 탭뿐). OS 알림을 띄우려면 Folderss 본체의 계약을 바꿔야 한다.
5. **누적 카운터는 인스턴스 재시작·통계 초기화·캐시 밀려남으로 리셋된다.** 단순 뺄셈은 음수나 거짓 급증을 만든다.
6. **SQL 문장에는 업무 데이터가 들어 있을 수 있다**(리터럴로 쓴 주민번호·고객명 등). 디스크에 남기면 보안 문제다.
7. **Oracle AWR(DBA_HIST_*)은 Diagnostic Pack 라이선스가 있어야 조회할 수 있다.** 조회만 해도 라이선스 사용으로 잡힌다.

## 3. 수집·저장 방식 비교

| 방식 | 내용 | 장점 | 단점·위험 |
|---|---|---|---|
| A. 메모리(창이 열린 동안) | 스냅샷을 링 버퍼에 보관, 창을 닫으면 사라짐 | 디스크·보안 문제 없음, 구현 작음, Q1·Q2 해결 | 창을 닫으면 끝, Q3·Q4 불가 |
| B. 로컬 파일(플러그인 데이터 폴더) | 숫자 지표만 주기적으로 파일에 추가 | 창을 다시 열어도 이어짐, Q3 일부 | 구멍 많은 이력(창이 열렸을 때만), PC마다 다름, 파일 관리 필요 |
| C. 서버의 자체 이력 읽기 | SQL Server Query Store, Oracle AWR, (PostgreSQL은 없음) | 상시 수집된 진짜 이력, 구멍 없음 | DBMS마다 있음/없음이 다름, AWR은 라이선스, Query Store는 DB별로 켜야 함 |
| D. 서버에 수집 테이블·잡 만들기 | DBMS_SCHEDULER · pg_cron · SQL Agent로 상시 수집 | Q4까지 해결 | 운영 DB에 DDL, DBA 승인 필요, 플러그인 범위를 넘음 |

## 4. 권장안: 3단 구성

### 1단 — 메모리 이력 (A) — 먼저 한다

- 창이 열려 있는 동안 **이력 지표**를 따로 수집한다. 보고 있는 섹션만 다시 가져오는 지금의 새로 고침과 별개다.
- **구간 보기(Q1)**: [느린 SQL]·[대기 이벤트]에 "누적 / 최근 구간" 전환. 직전 스냅샷과 지금의 차이로 정렬한다. 예: "지난 5분 동안 소요가 가장 많이 늘어난 SQL".
- **추이(Q2)**: 머리에 작은 스파크라인 — 사용자 세션 수, 활성 세션 수, 잠금 대기 수, 테이블스페이스별 사용률.
- 보관: 지표마다 최근 N개(기본 120개 = 30초 간격 1시간). 창을 닫으면 버린다.

### 2단 — 로컬 파일 이력 (B) — 숫자만, 저빈도

- 저장하는 것: **숫자 지표만**(테이블스페이스 사용·크기, DB 크기, 세션 수, 로그 스위치 수). **SQL 문장·사용자 이름·호스트 이름은 저장하지 않는다**(제약 6).
- 주기: 창을 열 때 한 번, 열려 있는 동안 60분마다(테이블스페이스 조회는 무겁다).
- 위치: `<플러그인 데이터 폴더>\monitor-history\<DB 식별자>\YYYY-MM.jsonl` — 한 줄에 스냅샷 하나, 달마다 파일 하나. 보관 기간이 지난 달 파일은 지운다(기본 90일).
- 추세(Q3)는 **조건이 맞을 때만** 보인다: 점이 5개 이상이고 3일 이상에 걸쳐 있을 때. 아니면 "이력이 부족합니다(수집 2일, 4점)". 화면에 **수집한 구간**을 함께 보여서 구멍을 숨기지 않는다.
- "며칠 뒤 가득 참"은 일 단위 선형 회귀로 계산하되 **최대(자동 확장 한도) 기준**과 **지금 크기 기준**을 둘 다 보인다. 디스크 여유는 모르므로(TODO 6) 문구에 그 한계를 쓴다.

### 3단 — 서버 자체 이력 (C) — 있을 때만

- SQL Server: Query Store가 켜진 DB면 `sys.query_store_runtime_stats`로 "지난 24시간 느린 SQL"을 보인다. 꺼져 있으면 지금의 필요 조건 점검(주황 안내)으로 "Query Store를 켜세요"를 보인다.
- Oracle: `CONTROL_MANAGEMENT_PACK_ACCESS`가 `DIAGNOSTIC`을 포함할 때만 AWR(DBA_HIST_SQLSTAT·DBA_HIST_TBSPC_SPACE_USAGE)을 읽는다. 아니면 **조회하지 않는다**(라이선스 위반 방지). 이 값은 "라이선스가 있다"의 증거가 아니라 "설정상 켜져 있다"일 뿐이라 화면에 그 문구를 쓴다.
- PostgreSQL: 자체 이력이 없다. 1·2단만.

### 하지 않는 것 — D(서버에 수집 테이블·잡)

- 플러그인이 운영 DB에 DDL을 하지 않는다. 필요하면 나중에 "수집 스크립트 내보내기"(DBA가 검토하고 직접 설치)로만 다룬다.

## 5. 데이터 설계

### DB 식별자 — 접속 프로필 id가 아니다

접속 프로필은 이름을 바꾸거나 복제하거나 다른 DB로 고칠 수 있다. 이력이 섞이거나 끊기지 않게 **서버가 알려 주는 값**으로 묶는다.

| DBMS | 식별자 |
|---|---|
| Oracle | `V$DATABASE.DBID` + 인스턴스 이름(RAC 대비) |
| PostgreSQL | `pg_control_system().system_identifier` + 데이터베이스 이름 |
| SQL Server | `@@SERVERNAME` + `DB_NAME()` |

폴더 이름에는 해시를 쓰고, 원래 값은 파일 안 머리 줄에 둔다.

### 스냅샷 한 줄

```json
{"at":"2026-10-19T05:05:31Z","start":"2026-10-02T03:12:44Z","m":{"sessions":48,"active":7,"lock_waits":2,"db_mb":512340},"ts":{"MES_DATA":[191562,204800,204800],"MES_IDX":[88311,102400,102400]}}
```

- `at`은 UTC, `start`는 인스턴스 시작 시각(카운터 리셋 판정용).
- `ts`는 테이블스페이스별 [사용, 크기, 최대] MB.

### 누적 카운터의 차이 규칙

- `start`가 같고 지금 값 ≥ 이전 값이면 차이 = 지금 − 이전.
- `start`가 바뀌었거나 값이 줄었으면 **리셋**: 그 구간은 차이를 보이지 않고 "재시작/초기화로 구간 없음"이라고 표시한다(0으로 두지 않는다).
- 느린 SQL의 키: Oracle `SQL_ID + PLAN_HASH_VALUE`, PostgreSQL `queryid`, SQL Server `query_hash`. 직전에는 있었는데 지금 캐시에서 밀려난 문장은 차이를 알 수 없다 — 목록에서 빼고 개수만 알린다.

### 공급자 인터페이스 확장 (안)

화면이 DBMS를 모르는 지금 원칙을 지키려면, 이력 지표도 **긴 형식 한 장**으로 받는다.

```
IMonitorProvider
  + SqlQuery Identity()        // 열: DB_KEY, LABEL
  + SqlQuery HistorySample()   // 열: METRIC, ITEM, VALUE, STARTED_AT   (행마다 지표 하나)
  + MonitorSection 의 선택 항목 DeltaKey/DeltaColumns  // "최근 구간" 전환을 지원하는 섹션만
```

예: `('ts_used_mb', 'MES_DATA', 191562)`, `('sessions', NULL, 48)`. 지표 이름 목록은 공통 상수로 두고, DBMS가 줄 수 없는 지표는 행을 안 주면 된다.

## 6. 임계값·알림

- 임계값: 지표마다 경고·위험 두 값(지금 도넛의 80·90% 고정을 대체). 플러그인 설정에 저장하고, 접속별로 덮어쓸 수 있게 한다(운영은 더 낮게).
- 알림 채널과 한계:
  1. 모니터 창 머리 배지(경고 n · 위험 n) — 바로 가능.
  2. DB Helper 메시지 탭 — 바로 가능. 같은 지표는 상태가 바뀔 때만 한 번(새로 고침마다 쌓이지 않게).
  3. OS 알림(트레이) — **Folderss 계약 변경이 필요**(`IPluginManager.Notify(title, text, level)` 추가 → 계약 부 버전 올림, 본체 구현, 예제 플러그인 빌드 확인). 플러그인이 자체 트레이 아이콘을 만드는 방법은 Folderss 창과 따로 놀고 종료 처리가 위험해서 권하지 않는다.
- **알림은 창이 열려 있을 때만 울린다.** "아무도 안 볼 때"(Q4)는 이 설계로 풀리지 않는다는 점을 도움말에 명시한다.

## 7. 결정이 필요한 것

1. **2단(로컬 파일)을 할지.** 하지 않으면 Q3(가득 참 예측)은 3단(Query Store·AWR)이 있는 DB에서만 된다.
2. 2단을 한다면 **보관 기간**(기본 90일 제안)과 **저장 지표 범위**(숫자만 — SQL 문장은 절대 안 남김, 이것은 바꾸지 않기를 권함).
3. **수집 주기**: 1단 30초(제안), 2단 60분(제안). 운영 DB 부하를 고려해 접속별로 끌 수 있어야 하는지.
4. **OS 알림을 위해 Folderss 계약을 바꿀지.** 바꾸면 두 저장소를 함께 고쳐야 하고 계약 버전이 오른다.
5. **AWR 읽기를 넣을지.** 넣는다면 `CONTROL_MANAGEMENT_PACK_ACCESS` 확인만으로 충분한지(라이선스 판단은 회사 몫).

## 8. 단계와 완료 조건

| 단계 | 내용 | 완료 조건(검증 가능) |
|---|---|---|
| 5-1 | 1단 메모리 이력: 구간 보기(느린 SQL·대기), 스파크라인 | 차이·리셋 규칙 단위 테스트(재시작·감소·캐시 밀림 경우), 창을 닫으면 메모리 해제 |
| 5-2 | 임계값 설정 + 창 배지 + 메시지 탭(상태 변화 때만) | 임계값 경계값 테스트, 같은 상태에서 메시지가 쌓이지 않음 테스트 |
| 5-3 | 2단 로컬 파일 | DB 식별자 테스트(프로필 복제·이름 변경에도 같은 폴더), 보관 기간 정리 테스트, 파일에 SQL 문장이 없음을 확인하는 테스트, 깨진 줄은 건너뜀 |
| 5-4 | 추세(가득 참 예측) | 점 부족·구간 부족이면 예측을 숨김 테스트, 회귀 계산 테스트 |
| 5-5 | 3단 서버 이력(Query Store · AWR) | 꺼져 있으면 필요 조건 안내, AWR은 팩 설정이 없으면 조회 SQL을 보내지 않음 |
| 5-6 | (계약 변경 시) OS 알림 | Folderss 계약·본체·예제 플러그인 빌드 |

권장 순서: 5-1 → 5-2 → (결정 1에 따라) 5-3 → 5-4. 5-5·5-6은 결정 4·5에 달렸다.
