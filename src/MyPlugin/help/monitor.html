성능 모니터

도구 > 성능 모니터…(트리에서 대상 DB를 고른 뒤) 또는 트리의 DB 행 오른쪽 메뉴에서 엽니다. 연결이 없으면 먼저 연결합니다. 창은 모달이 아니라 열어 둔 채 SQL을 쓸 수 있고, DB마다 하나만 뜹니다(같은 DB에서 다시 열면 그 창이 앞으로).

  • 섹션은 처음 고를 때 가져옵니다. [새로 고침](F5)과 자동 새로 고침(끔 · 5초 · 15초 · 60초)은 보고 있는 섹션만 다시 가져옵니다.
  • 저장 공간 섹션(Oracle 테이블스페이스 · SQL Server 데이터 파일)은 표 위 대시보드에 행마다 사용률 도넛 차트를 그립니다(가운데 %, 아래 이름과 사용/전체 MB). 80% 이상은 경고색, 90% 이상은 위험색이고 최대 12개까지 보인 뒤 나머지는 "외 N개는 표에서"로 알립니다. PostgreSQL 테이블스페이스는 한도가 없어 차트가 없습니다.
  • 저장 공간 섹션에서 표의 행이나 도넛을 누르면 표 아래(분할선으로 크기 조절)에 상세 목록이 뜹니다. Oracle은 [데이터 파일](파일·크기·자동 확장·최대·증가·상태)과 [세그먼트](DBA_SEGMENTS — 테이블·인덱스·LOB, 파티션은 이름으로 합쳐 큰 것부터 200개), PostgreSQL은 그 테이블스페이스에 저장된 객체(현재 DB), SQL Server는 그 파일이 속한 파일 그룹의 객체(파일 단위로는 나뉘지 않음, 로그 파일은 비어 있음)입니다.
  • 잠금·세션 섹션에서 행을 누르면 아래에 [SQL 전문]·[실행 계획]·[세션 정보/통계]가 보입니다. SQL 전문과 실행 계획은 표가 아니라 글 상자라 그대로 복사할 수 있습니다. Oracle은 V$SQL·DBMS_XPLAN.DISPLAY_CURSOR(세션이 쉬는 중이면 직전 문장)·V$SESSTAT, SQL Server는 sys.dm_exec_sql_text(쉬는 세션은 마지막 문장)·sys.dm_exec_text_query_plan(실행 중일 때만, XML), PostgreSQL은 pg_stat_activity.query(서버가 track_activity_query_size 기본 1,024자까지만 보관)와 세션 정보이고 다른 세션의 실행 계획은 주지 않습니다.
  • 표의 오른쪽 메뉴 [세션 종료…]는 고른 행의 세션 번호로 ALTER SYSTEM KILL SESSION 'sid,serial#' IMMEDIATE · SELECT pg_terminate_backend(pid) · KILL n을 만들어 문장·경고·확인 체크 대화상자를 거친 뒤 실행하고 섹션을 다시 가져옵니다. 그 세션의 커밋하지 않은 변경은 롤백되고 사용자는 끊깁니다. 읽기 전용 접속에서는 막히며, Oracle은 ALTER SYSTEM 권한이 있어야 합니다.
  • 표는 결과 그리드와 같아 열 머리로 정렬하고 Ctrl+C·오른쪽 메뉴로 복사합니다. 섹션 하나는 최대 2,000행까지 가져옵니다.
  • 조회는 그 DB의 세션(트랜잭션)을 SQL 탭과 함께 씁니다. 그 DB에서 문장이 실행 중이면 기다리지 않고 알립니다. 자료를 바꾸는 문장은 없습니다.
  • 확장 설치나 서버 버전이 필요한 섹션(지금은 PostgreSQL 느린 SQL의 pg_stat_statements·13 이상)은 가져오기 전에 점검해, 안 되면 조회하지 않고 "설치·설정 필요 — …"를 주황색으로 보입니다. 무엇을 어떻게 설치해야 하는지(shared_preload_libraries → 재시작 → CREATE EXTENSION)가 그 글에 있습니다. 권한 오류(빨강)와는 다른 색입니다. 접속이 이 PC(localhost · 127.0.0.1 · 컴퓨터 이름)의 서버면 직접 설치할 수 있으므로, 단계별 절차와 문서·내려받기 링크를 DB Helper 메시지 탭에 함께 남깁니다(원격 서버는 관리자에게 전달해야 하므로 남기지 않음).
  • 권한이 없는 섹션은 그 섹션만 "권한이 없어 가져오지 못했습니다 — 필요 권한: …"으로 보이고 다른 섹션은 그대로 동작합니다.
